# Deployment & release

## Backend → Render (free tier)

### Current deployment

| Resource | Value |
| --- | --- |
| API | <https://quickbite-api-0zul.onrender.com> (health: `/health`) |
| Service | `quickbite-api` · Node · Singapore · free · auto-deploys on push to `main` |
| Database | `quickbite-db` · PostgreSQL 16 · Singapore · free (expires 30 days after creation — upgrade or recreate) |
| Build | `cd backend && npm install && npx prisma migrate deploy && node prisma/seed.js` |
| Start | `cd backend && npm start` |

`DATABASE_URL` is the database's **Internal Database URL** (same region, so traffic stays on Render's private network).

### Recreating it from scratch (Blueprint)

The repo contains a [Render Blueprint](../render.yaml) that creates **a PostgreSQL database and
the Node web service** together, wires `DATABASE_URL`, generates JWT/admin secrets, runs
migrations and seeds demo data.

1. Sign in at <https://dashboard.render.com> with GitHub.
2. **New → Blueprint** → select the `QuickBite` repository → **Apply**.
3. Wait for the first deploy (≈5 min). Open `https://<service>.onrender.com/health` — you should see
   `{"status":"ok","database":"ok", …}`.
4. Your API base URL is `https://<service>.onrender.com`. If the service name isn't
   `quickbite-api`, update `API_BASE_URL` in `ios/Config/Release.xcconfig` (or in the app:
   Profile → Server & diagnostics → Change server URL).

Things to know about the free tier:

* The web service **sleeps after ~15 minutes idle**; the first request afterwards takes ~30–60 s.
  Open `/health` a minute before a live demo.
* Free PostgreSQL databases **expire after 30 days** — upgrade or recreate before then.
* Every push to `main` redeploys automatically (`autoDeploy: true`).

### Environment variables

See [`backend/.env.example`](../backend/.env.example). Secrets are set in the Render dashboard
(Environment tab), never committed.

| Variable | Required | Purpose |
| --- | --- | --- |
| `DATABASE_URL` | ✅ | Set by the blueprint |
| `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET` | ✅ | Generated by the blueprint |
| `ADMIN_API_KEY` | | Staff endpoint for moving orders by hand |
| `MOCK_PAYMENTS` | | `true` enables the labelled demo payment provider |
| `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET` | | Razorpay **test mode** keys (Dashboard → Settings → API Keys, in Test Mode) |
| `SOCIAL_LOGIN_DEMO` | | `true` accepts `demo:<email>` social tokens — turn **off** for a real launch |
| `APPLE_BUNDLE_ID`, `GOOGLE_CLIENT_IDS` | | Audiences for real Apple / Google identity tokens |
| `FCM_PROJECT_ID`, `FCM_CLIENT_EMAIL`, `FCM_PRIVATE_KEY` | | Firebase service account (push) |
| `DEMO_ORDER_PROGRESSION`, `DEMO_STEP_SECONDS` | | Auto-advance orders for demos |

### Migrations

`buildCommand` runs `npx prisma migrate deploy` on every deploy, so committed migrations are
applied automatically. Create new ones with `npx prisma migrate dev --name <change>` locally (or
the **Generate Prisma migration** workflow).

### Razorpay webhook (optional)

Razorpay Dashboard (Test Mode) → Webhooks → Add: URL
`https://<service>.onrender.com/api/v1/payments/webhook/razorpay`, events `payment.captured`,
`payment.failed`, and put the same secret in `RAZORPAY_WEBHOOK_SECRET`.

## iOS — build, sign, TestFlight

### Local build
```bash
brew install xcodegen cocoapods
cd ios
xcodegen generate
pod install
open QuickBite.xcworkspace          # always the .xcworkspace (CocoaPods)
```

### Code signing (device / TestFlight)
1. Join the Apple Developer Program (paid) — required for TestFlight, push and Sign in with Apple on device.
2. Set your team: `DEVELOPMENT_TEAM` in `ios/project.yml` (then `xcodegen generate`) or Xcode →
   target → Signing & Capabilities. Change `PRODUCT_BUNDLE_IDENTIFIER` if `com.quickbite.app` is taken.
3. Add capabilities **Push Notifications** and **Sign in with Apple** (the simulator build already
   embeds them from `QuickBite.entitlements`).

### fastlane
```bash
cd ios
bundle install
bundle exec fastlane unit      # unit tests
bundle exec fastlane test      # unit + UI tests
bundle exec fastlane build     # Release build, no signing
bundle exec fastlane beta      # signed build → TestFlight
```

`beta` expects:
* an **App Store Connect API key**: `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_CONTENT` (base64 of the .p8);
* **match** for certificates/profiles: `MATCH_GIT_URL` (a private repo) and `MATCH_PASSWORD`
  — run `bundle exec fastlane match appstore` once to create them;
* the app record created in App Store Connect with the same bundle id.

> Status: the TestFlight lane is configured but **has not been run** (it needs your Apple
> Developer account). Nothing has been published to TestFlight or the App Store.

## Optional integrations

### Firebase Cloud Messaging (push)
1. Firebase console → add an iOS app with your bundle id → download `GoogleService-Info.plist`
   into `ios/QuickBite/Resources/` (git-ignored) → `xcodegen generate`.
2. Upload your APNs auth key (.p8) in Firebase → Project settings → Cloud Messaging.
3. Service account (Project settings → Service accounts → Generate key) → set `FCM_PROJECT_ID`,
   `FCM_CLIENT_EMAIL`, `FCM_PRIVATE_KEY` on the server.
4. Push requires a real device. Without any of this, order updates still arrive in-app
   (Socket.IO banners + notification inbox).

### Google Sign-In
Google Cloud console → OAuth client (iOS) → put the client id / reversed id in
`ios/QuickBite/Resources/Secrets.xcconfig` (copy `ios/Config/Secrets.example.xcconfig`) and add the
same client id to `GOOGLE_CLIENT_IDS` on the server.

### Sign in with Apple
Works on a simulator signed into an Apple ID and on devices with the capability enabled. The
server verifies tokens against `APPLE_BUNDLE_ID`.
